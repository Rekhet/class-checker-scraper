Maintenance

Keeping the catalog fresh, recovering fall timing, backups, and the handful of failure modes worth recognising.

Refresh cadence

Two passes, two rhythms — the server does not self-schedule; drive these from cron, a timer, or the admin button.

PassCostSuggested cadence
Full rebuild (Excel + timing) Heavy — one Excel/term, plus a 168-cell sweep for not-yet-published terms Daily, or whenever a timetable changes
Counts-only overlay Light — one paginated roster/term Often during registration (e.g. every few minutes)
# existing full update timer (cart excluded)
systemctl --user enable --now class-checker.update.timer

# bounded two-day cart window
./scripts/start-cart-window \
  --start-date 2026-08-04 \
  --year 2026 \
  --semester fall \
  --timezone Asia/Seoul \
  --disable-broad-timer
⏱️

The scheduled full update collects the catalog, enrollment, and grading components, but not cart. The bounded worker is the only scheduled cart collector. Both use the same host-local data/.crawl.lock, including JSON export and Git publication. The old broad class-checker.update-counts.timer should remain disabled.

Worker safety and recovery

All database, export, and publication writers share the advisory flock(2) at data/.crawl.lock. The zero-length lock file may remain after a run; its open file descriptor and kernel lock are what provide protection. A successful run, failed worker, exception, or systemd interruption releases the lock. The user services use KillMode=control-group, so systemd terminates the wrapper and its child processes together.

SituationCurrent behavior
Computer sleeps A suspended lock owner normally keeps the lock. A waiter can wait up to 900 seconds, then exits with status 75. Missed cart activations are not replayed; persistent full/cleanup timers may receive a catch-up activation.
Overlapping requests The same oneshot service does not run in parallel. Separate full, cart, and cleanup services serialize through the shared lock; a waiter exits 75 after the lock timeout rather than creating a durable queue.
Long collector or cleanup The cart service has a 20-minute timeout and cleanup has 35 minutes. Cleanup waits up to 1800 seconds for the worker and lock, then leaves window state for manual recovery. It also requires the collector to report Result=success and to have actually started before deleting generated files.

Automatic retry after lock contention or a failed/never-run final sample, forced-count cart semantics, transactional rebuild recovery, publication staging isolation, and direct-wrapper process-group hardening remain deferred. The full rationale is in the implementation audit.

Fall timing recovery

Before SNU publishes a term's timetable into the Excel, its 수업교시 column is empty. The crawl detects this (low Excel-timed ratio) and recovers approximate timing from the live search cells (±30 min on the end). Nothing to do manually: once the Excel carries exact times, the next full rebuild overrides the coarse blocks automatically. Track progress in the time-assigned % panel.

Backups

The catalog is a single file. Back it up by copying it (ideally while no crawl is writing):

cp data/classes.db  backups/classes-$(date +%F).db   # SQLite
cp data/turso.db    backups/turso-$(date +%F).db     # local libSQL

A rebuild is always reproducible from SNU, so backups are convenience, not safety. crawl_runs retains the history of every refresh.

Updating & verifying

# refresh dependencies after a pull
VIRTUAL_ENV=.venv uv pip install -e ".[turso,speed]"
.venv/bin/playwright install chromium

# health check
curl -s http://127.0.0.1:8011/api/status | python3 -m json.tool

/api/status returns the active backend, row counts, the last crawl run, and live refresh progress — the quickest signal that things are healthy.

Troubleshooting

SymptomCause & fix
Excel download is empty / 0 bytes The EX request needs the full form + a valid term seed; an empty term (e.g. winter with no classes) legitimately returns nothing. A fresh session may hit an interstitial — the fetch re-mints and retries on missing .xls magic.
cc100ajax … non-JSON / empty term list The term-list call needs a seed term code (SEED_SHTM); a dropped session is re-minted on the next request.
Session mint fails Run playwright install chromium. Minting visits the sugang home to collect JSESSIONID + enter=Y, then validates with a test POST.
database is locked A crawl and the server are writing/holding the same local file. Stop the server during heavy rebuilds, or serve from a replica.
Refresh returns 401 ADMIN_TOKEN is set — send it as the X-Admin-Token header.
Saved timetable shows old times Reconciliation runs on load and after a refresh; reload the page, or trigger a refresh, to re-sync via /api/lookup.
2학기 (fall) shows few timed classes Expected before SNU publishes fall times. Timing fills in from search cells and is upgraded to exact on later rebuilds.
Port already in use Another server instance is running — change PORT or stop the old process.
