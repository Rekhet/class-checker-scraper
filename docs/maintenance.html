Maintenance

Keeping the catalog fresh, recovering fall timing, backups, and the handful of failure modes worth recognising.

Refresh cadence

Two passes, two rhythms — the server does not self-schedule; drive these from cron, a timer, or the admin button.

PassCostSuggested cadence
Full rebuild (Excel + timing) Heavy — one Excel/term, plus a 168-cell sweep for not-yet-published terms Daily, or whenever a timetable changes
Counts-only overlay Light — one paginated roster/term; commits locally per run Often during registration (e.g. every few minutes)
# existing full update timer (cart excluded)
systemctl --user enable --now class-checker.update.timer

# bounded two-day cart window
./scripts/start-cart-window \
  --start-date 2026-08-04 \
  --year 2026 \
  --semester fall \
  --timezone Asia/Seoul \
  --disable-broad-timer
# bounded multi-date enrollment window
./scripts/start-enrollment-window \
  --dates 2026-08-07,2026-08-10,2026-08-11 \
  --start-time 08:30 \
  --end-time 16:30 \
  --burst-minutes 30 \
  --burst-interval 5 \
  --interval 10 \
  --year 2026 \
  --semester fall \
  --timezone Asia/Seoul \
  --disable-broad-timer
⏱️

The scheduled full update collects the catalog, enrollment, and grading components, but not cart. The bounded cart worker collects cart during its own window, and the bounded enrollment worker collects live applied/enrolled counts on the listed registration days. Both use the same host-local data/.crawl.lock, including JSON export and Git publication. The old broad class-checker.update-counts.timer should remain disabled.

The enrollment timer samples every five minutes for the first 30 minutes of each listed date, including both endpoints, then every ten minutes through the 16:30 end time. The current three-date window therefore has 52 runs per date and 156 runs total. The cadence options are explicit in the installation command so a future semester can reproduce the same schedule. They do not change shared-lock ordering against the hourly full update.

Frequent bounded trend runs commit their generated JSON in the public web/ repository but do not push each commit. The hourly class-checker.update.timer performs the full update and is the scheduled push boundary, publishing the accumulated local commits once per hour. This keeps the trend cadence independent from remote publication cadence.

The worker service templates create the private user-runtime directory %t/class-checker and export it as TMPDIR, keeping Playwright's temporary Chromium profiles out of the shared /tmp filesystem. During the 2026-08-05 audit, two runs failed because that shared filesystem rejected Chromium profile writes. After the templates were refreshed, the 01:00 run completed successfully for all 8,625 classes and produced 96 trend samples.

Cart identity and NULL audit

The Excel catalog uses subh_cd=000 because that export does not carry SNU's live sub-course code. The search page may return a different subh_cd, so the counts overlay first tries the complete identity, then falls back to the stable (sbjt_cd, lt_no) pair when it maps to exactly one catalog row. If that pair is duplicated, matching course name, professor, and department may disambiguate it; unresolved ambiguity is skipped rather than writing a count to the wrong class.

# read-only storage + live-site audit
./scripts/audit-cart-counts --year 2026 --term fall --live

# machine-readable report
./scripts/audit-cart-counts --year 2026 --term fall --live --json

A stored NULL is expected outside the configured cart window. With --live, the audit distinguishes site-side NULLs, safely recoverable non-negative live values, ambiguous identities, and catalog rows absent from the live roster.

Worker safety and recovery

All database, export, and publication writers share the advisory flock(2) at data/.crawl.lock. The zero-length lock file may remain after a run; its open file descriptor and kernel lock are what provide protection. A successful run, failed worker, exception, or systemd interruption releases the lock. The user services use KillMode=control-group, so systemd terminates the wrapper and its child processes together.

SituationCurrent behavior
Computer sleeps A suspended lock owner normally keeps the lock. A waiter can wait up to 900 seconds, then exits with status 75. Missed cart activations are not replayed; persistent full/cleanup timers may receive a catch-up activation.
Overlapping requests The same oneshot service does not run in parallel. Separate full, cart, enrollment, and cleanup services serialize through the shared lock; a waiter exits 75 after the lock timeout rather than creating a durable queue.
Long collector or cleanup The cart service has a 20-minute timeout and cleanup has 35 minutes. Cleanup waits up to 1800 seconds for the worker and lock, then leaves window state for manual recovery. It also requires the collector to report Result=success and to have actually started before deleting generated files.

Automatic retry after lock contention or a failed/never-run final sample, forced-count cart semantics, transactional rebuild recovery, publication staging isolation, and direct-wrapper process-group hardening remain deferred. The full rationale is in the implementation audit.

Frontend JSON boundaries

The public static page validates the shape and data types of its catalog, trend, explorer, graduation, import, local-storage, and optional status payloads before using them. A malformed term is skipped locally; malformed trend, explorer, or graduation data disables only that feature. Trend metrics must be integers or null, and all metric arrays must align with their timestamp array. The trend tooltip uses DOM text nodes, so values from the published JSON are not parsed as HTML.

This validation deliberately does not cap payload size or array length. It protects structure and types while allowing legitimate future growth. The browser regression suite can be run with:

TEST_TMPDIR="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}/class-checker-json-validation"
mkdir -p "$TEST_TMPDIR"
TMPDIR="$TEST_TMPDIR" python3 -m unittest \
  web.tests.test_json_validation web.tests.test_search_cart

Fall timing recovery

Before SNU publishes a term's timetable into the Excel, its 수업교시 column is empty. The crawl detects this (low Excel-timed ratio) and recovers approximate timing from the live search cells (±30 min on the end). Nothing to do manually: once the Excel carries exact times, the next full rebuild overrides the coarse blocks automatically. Track progress in the time-assigned % panel.

Backups

The catalog is a single file. Back it up by copying it (ideally while no crawl is writing):

cp data/classes.db  backups/classes-$(date +%F).db   # SQLite
cp data/turso.db    backups/turso-$(date +%F).db     # local libSQL

Recovery artifacts are kept under backups/ in the private automation repository. The June cleanup archive backups/class-checker-june-samples-20260804.jsonl.gz contains 177,120 historical samples from 2026-06-21 through 2026-06-23. It is not imported by scheduled workers; restore it only as an explicit recovery operation.

A rebuild is always reproducible from SNU, so backups are convenience, not safety. crawl_runs retains the history of every refresh.

Updating & verifying

# refresh dependencies after a pull
VIRTUAL_ENV=.venv uv pip install -e ".[turso,speed]"
.venv/bin/playwright install chromium

# health check
curl -s http://127.0.0.1:8011/api/status | python3 -m json.tool

/api/status returns the active backend, row counts, the last crawl run, and live refresh progress — the quickest signal that things are healthy.

Troubleshooting

SymptomCause & fix
Excel download is empty / 0 bytes The EX request needs the full form + a valid term seed; an empty term (e.g. winter with no classes) legitimately returns nothing. A fresh session may hit an interstitial — the fetch re-mints and retries on missing .xls magic.
cc100ajax … non-JSON / empty term list The term-list call needs a seed term code (SEED_SHTM); a dropped session is re-minted on the next request.
Session mint fails Run playwright install chromium. Minting visits the sugang home to collect JSESSIONID + enter=Y, then validates with a test POST.
database is locked A crawl and the server are writing/holding the same local file. Stop the server during heavy rebuilds, or serve from a replica.
Playwright reports TargetClosedError or Chromium cannot create its cache/profile Refresh the installed worker units from systemd/ and run systemctl --user daemon-reload. The units must set TMPDIR=%t/class-checker; do not rely on the shared /tmp filesystem.
Refresh returns 401 ADMIN_TOKEN is set — send it as the X-Admin-Token header.
Saved timetable shows old times Reconciliation runs on load and after a refresh; reload the page, or trigger a refresh, to re-sync via /api/lookup.
2학기 (fall) shows few timed classes Expected before SNU publishes fall times. Timing fills in from search cells and is upgraded to exact on later rebuilds.
Port already in use Another server instance is running — change PORT or stop the old process.
