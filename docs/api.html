API & Frontend

A small JSON API over the catalog, plus the vanilla-JS UI that consumes it. The temporary timetable lives entirely in the browser (localStorage); the server is stateless about it.

Read endpoints

EndpointReturns
GET /api/terms{terms:[{term,year,label}]}
GET /api/departments{departments:[…]} — distinct names, for autocomplete
GET /api/classifications{classifications:[…]} — 과정 + 이수구분 tags, most common first
GET /api/timestats{stats:[{term,label,total,timed,timeless}]}
GET /api/status{counts,last_run,backend,refresh}
GET /api/search?…{count,classes:[…]} (each class carries its slots)

Search parameters

All optional; combined with AND. Multi-value params repeat the key.

✳ level and classification are independent groups — OR within a group, AND (intersection) between them. Example: ?level=학사&classification=전필&classification=교양 → bachelor courses that are major-required or general-ed.

# classes named "경제", bachelor, on Monday
curl 'http://127.0.0.1:8011/api/search?name=경제&level=학사&day=0'

Write / refresh endpoints

Run a background crawl thread; poll /api/status for live progress. Gated by X-Admin-Token when ADMIN_TOKEN is set. Every POST — token or not — is refused with 403 when a browser marks it as coming from another site (Origin not matching Host, or Sec-Fetch-Site other than same-origin/none), and, without a token, when Host is not a loopback name (DNS rebinding). curl and other non-browser clients send neither header and are unaffected. /api/lookup accepts at most 2,000 keys.

Frontend features

Search & filters

  • Term, name, professor, day, period selectors.
  • Department — type-ahead <datalist> over real department names.
  • 과정 (Level) and 이수구분 (Type) — independent checkbox dropdowns; OR within, intersection between.
  • Each result shows its current 장바구니 count when available, plus 경쟁률 as cart/quota when the quota is positive, classification chips, and either its time ranges or a 시간미정 TBA chip.

Proportional timetable

  • Blocks are positioned by start time with height proportional to duration — a 90-minute class visibly spans 90 minutes.
  • Overlapping classes on a day split into side-by-side lanes and get a conflict outline.
  • Each block shows the exact 09:00~10:15; click to remove.
  • Time-less (TBA) classes you add are listed beneath the grid rather than placed.
  • The whole timetable persists in localStorage and can be cleared.

Live reconciliation

On page load and after any refresh, the saved timetable is reconciled against the catalog via /api/lookup: changed meeting times are corrected and flagged 시간 변경, cancelled classes are flagged 폐강, and a banner summarises what moved.

Time-assigned stats

A dedicated panel shows the share of classes that have a scheduled time, per semester (or all) — a quick read on how complete a term's timetable is. Fall starts low (timetable not yet published) and climbs as SNU fills it in.

Admin refresh

Pick a semester (or 전체 All) and press DB 새로고침. A progress bar streams the Excel download, cell sweep, and count overlay phases; on completion the search results, stats, and saved timetable all refresh.

Static JSON validation

The static frontend treats its JSON files and browser-imported files as data interfaces, not as arbitrary JavaScript. The catalog index validates term identities and JSON filenames; class rows validate their scalar fields, nullable counts, classifications, and meeting slots; trend data (format v: 2) requires rising integer epoch seconds in t and well-formed change-point encodings (integer indices below t.length, integer-or-null values) for the pass mask and every class metric. The explorer and graduation indexes validate their cross-reference types before building maps.

Trend payload (v2, since 2026-09-27)

data/trend/trend_<year>_<term>.json (the live window) and its frozen chunks …_wNNN.json share one shape:

{"v": 2, "updated": "2026-09-27T22:02:31", "tz": "Asia/Seoul",
 "t": [1790..., ...],                 // pass times, epoch seconds
 "m": {"a": 1, "e": 1},               // metrics each pass collected
 "series": {"M1522.000900(001)": {"a": [0, 12, 57, 13], "e": 12, "q": 30}}}

Each series value is a change-point list: absent/null = every pass null, an integer = constant, [i0, v0, i1, v1, …] = v_k from pass i_k until the next index. The decoder nulls a value whose pass did not collect that metric (m, same encoding over 0/1; quota is always collected), and a metric no pass in the window collected is omitted everywhere. Times are absolute and labelled in tz, so the chart reads KST in any browser; its x axis is time, and a collection gap longer than three hours breaks the line. The live file starts at the newest complete 240-pass chunk, so it never overlaps a chunk the UI pages to (trendArchives in the class index counts the chunks before it). The dense v1 files were ~27 MB each; v2 windows are ~0.34 MB (46 KB gzipped). export_json.decode_trend() expands a payload back to dense arrays.

A malformed term file is isolated to that term and contributes no search rows. A malformed trend, explorer, or graduation payload fails only its feature and shows the feature's fallback state. Invalid imported timetable or wishlist entries are rejected before catalog resolution, and malformed local-storage entries are ignored individually. Trend tooltips are built with DOM text nodes, so JSON values are not interpolated into HTML.

There is intentionally no payload-size or array-length cap in this layer. Validation checks shape, references, and data types while allowing valid future terms and larger catalogs.
