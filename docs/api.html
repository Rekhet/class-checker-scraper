API & Frontend

A small JSON API over the catalog, plus the vanilla-JS UI that consumes it. The temporary timetable lives entirely in the browser (localStorage); the server is stateless about it.

Read endpoints

EndpointReturns
GET /api/terms{terms:[{term,year,label}]}
GET /api/departments{departments:[…]} — distinct names, for autocomplete
GET /api/classifications{classifications:[…]} — 과정 + 이수구분 tags, most common first
GET /api/timestats{stats:[{term,label,total,timed,timeless}]}
GET /api/status{counts,last_run,backend,refresh}
GET /api/search?…{count,classes:[…]} (each class carries its slots)

Search parameters

All optional; combined with AND. Multi-value params repeat the key.

ParamMeaning
termsemester cmmnCd
name, professor, departmentsubstring (LIKE) match
classification ✳이수구분 tag(s) — OR within, e.g. 전필, 교양
level ✳과정 tag(s) — OR within, e.g. 학사, 대학원
day0 = Mon … 6 = Sun (matches a meeting block)
periodstart hour − 8
limitmax rows (default 500)

✳ level and classification are independent groups — OR within a group, AND (intersection) between them. Example: ?level=학사&classification=전필&classification=교양 → bachelor courses that are major-required or general-ed.

# classes named "경제", bachelor, on Monday
curl 'http://127.0.0.1:8011/api/search?name=경제&level=학사&day=0'

Write / refresh endpoints

Run a background crawl thread; poll /api/status for live progress. Gated by X-Admin-Token when ADMIN_TOKEN is set.

EndpointBodyAction
POST /api/refresh{years,terms}Full Excel rebuild + timing recovery + counts for the scoped terms
POST /api/refresh-counts{years,terms}Fast counts-only overlay (no Excel, no cell sweep)
POST /api/lookup{keys:[[term,sbjt_cd,lt_no],…]}Current records (with slots) for saved-timetable reconciliation

Frontend features

Search & filters

  • Term, name, professor, day, period selectors.
  • Department — type-ahead <datalist> over real department names.
  • 과정 (Level) and 이수구분 (Type) — independent checkbox dropdowns; OR within, intersection between.
  • Each result shows its current 장바구니 count when available, plus 경쟁률 as cart/quota when the quota is positive, classification chips, and either its time ranges or a 시간미정 TBA chip.

Proportional timetable

  • Blocks are positioned by start time with height proportional to duration — a 90-minute class visibly spans 90 minutes.
  • Overlapping classes on a day split into side-by-side lanes and get a conflict outline.
  • Each block shows the exact 09:00~10:15; click to remove.
  • Time-less (TBA) classes you add are listed beneath the grid rather than placed.
  • The whole timetable persists in localStorage and can be cleared.

Live reconciliation

On page load and after any refresh, the saved timetable is reconciled against the catalog via /api/lookup: changed meeting times are corrected and flagged 시간 변경, cancelled classes are flagged 폐강, and a banner summarises what moved.

Time-assigned stats

A dedicated panel shows the share of classes that have a scheduled time, per semester (or all) — a quick read on how complete a term's timetable is. Fall starts low (timetable not yet published) and climbs as SNU fills it in.

Admin refresh

Pick a semester (or 전체 All) and press DB 새로고침. A progress bar streams the Excel download, cell sweep, and count overlay phases; on completion the search results, stats, and saved timetable all refresh.
